HOST: Data and DevOps tools also appear in your résumé—SQL, PySpark, BigQuery, Cosmos DB, Docker, CI/CD pipelines. How do these fit into your AI pipelines?

CI/CD pipelines ensure that updates to prompts or model versions are tested and deployed reliably.
HOST: You’ve also listed TensorFlow, PyTorch, and Keras. Do you still train models from scratch, or is most of your work inference‑focused?
EXPERT: Mostly inference‑focused. I fine‑tune pre‑trained models using LoRA or QLoRA, which reduces the compute needed. However, I keep the core ML frameworks handy for custom layers or when we need to prototype a new architecture.
HOST: Let’s dive into your projects. First, the Financial Data Query Assistant. What was the core challenge there?
EXPERT: The main challenge was translating natural language financial queries into accurate SQL statements. We built a FastAPI orchestration layer that extracts entities with regular expressions, validates parameters, and asks follow‑up questions when information is missing. Then we used Databricks Genie to generate the SQL, execute it, and summarize the results.
HOST: How did you ensure the generated SQL was reliable?
EXPERT: We implemented an LLM‑as‑a‑Judge evaluation framework that measures SQL Query Generation Error Rate, faithfulness to the source data, and answer relevance. This systematic evaluation helped us iterate on prompts and improve accuracy.
HOST: You also mentioned DSPy prompt optimization with GEPA and MIPROv2. How did those techniques help?
EXPERT: GEPA and MIPROv2 are systematic ways to explore prompt variations and select the best performing ones. By applying them, we reduced the error rate and increased the relevance of the chatbot’s answers, all while keeping the prompt size manageable.
HOST: Observability was another focus. What does that look like in practice?
EXPERT: We added logging and metrics around each step—entity extraction latency, LLM response times, SQL execution duration, and evaluation scores. This lets us monitor the pipeline in real time and quickly spot regressions.
HOST: Moving on to the RDA Incident Support Bot. How does that system help enterprise support teams?
EXPERT: The bot integrates with Microsoft Teams and ServiceNow. When an incident is reported, the bot uses RAG to retrieve relevant knowledge articles, analyzes the incident description, and generates step‑by‑step diagnostic workarounds. It presents these as interactive Adaptive Cards in Teams, allowing the user to apply a fix or automatically route the ticket to a higher tier.
HOST: You built a document‑update tracking service for that bot. Why was that necessary?
EXPERT: Knowledge bases evolve. The tracking service watches for updates to source documents, re‑indexes them, and refreshes the RAG vector store. This ensures the bot always answers with the latest information.
HOST: Security again—what does a “secretless Azure architecture” entail?
EXPERT: It means we avoid hard‑coded credentials entirely. We use user‑assigned managed identities for the service, Azure Entra ID for SSO, and OAuth 2.0/OIDC for token exchange. The Bot Framework validates incoming webhooks, and we enforce PII handling controls throughout.
HOST: You also measured metrics like FCR, MTTR, RAG faithfulness, and context relevance. How did those inform improvements?
EXPERT: First‑Contact Resolution (FCR) and Mean Time to Resolve (MTTR) are business KPIs. By correlating them with RAG faithfulness and context relevance scores, we could see how better retrieval and more accurate generation directly reduced resolution times and increased successful first‑contact outcomes.
HOST: The AI‑Powered CRM Sales Conversation Validation project sounds complex. What problem were you solving?
EXPERT: We needed to automatically validate sales calls against 50 energy‑sector scripts, ensuring required disclosures, consent, and sales criteria were met. The system extracts entities, checks precision and recall against the script, and flags any missing or non‑compliant elements.
HOST: How did you handle call drops and ambiguous responses?
EXPERT: The orchestration logic preserves whatever data has been collected, detects missing fields, and triggers an LLM fallback when the user’s response is unclear. If the fallback still can’t resolve the ambiguity, a voice‑agent follows up later to complete the conversation.
HOST: You integrated Sarvam AI models for Indian‑language transcription. How did they compare to services like Twilio or Dialogflow CX?
EXPERT: In our tests, Sarvam AI’s transcription accuracy was higher, especially for regional accents and code‑mixed language. We measured Word Error Rate and found Sarvam consistently outperformed the alternatives, which improved downstream entity extraction.
HOST: The deployment used GCP services like Cloud Run, Scheduler, and Cloud Run Jobs. What role did those play?
EXPERT: Cloud Run hosts the FastAPI services in a serverless container, Scheduler triggers periodic jobs such as re‑indexing the knowledge base, and Cloud Run Jobs handle batch tasks like large‑scale transcription. Speech‑to‑Text and Text‑to‑Speech services enable the voice‑agent component, and we monitor everything with an observability layer.
